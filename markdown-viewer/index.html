Markdown Viewer: Render .md Files for Confluence

Render Markdown and .md files in pages, with tables, task lists and code blocks.

Overview

Show Markdown on Confluence pages as formatted content, so READMEs, runbooks and docs written in Markdown are as easy to read as the rest of the page.

  • From Markdown pasted inside the macro (in a code block), or from a .md file attached to the page.
  • GitHub Flavored Markdown: headings, paragraphs, nested bulleted and numbered lists, task lists, tables, code blocks with syntax highlighting, quotes, horizontal rules, footnotes, reference-style links, links and automatic links, bold, italic, strikethrough and inline code.
  • Images attached to the page or embedded in the file (data URIs), shown where the Markdown puts them.
  • An optional table of contents built from the headings.
  • YAML front matter (the --- block at the top of many .md files) and HTML comments are hidden.
  • Code is shown in Confluence's own code style, with the language taken from the code fence (``` `python ```).

Getting started

  1. A Confluence administrator installs the app from its Atlassian Marketplace listing.
  2. Edit a page, type /Markdown Viewer and insert the macro.
  3. Either:
    • Paste the Markdown inside the macro, in a code block. Type ``` ` ``` inside the macro to start a code block, then paste. In a code block the editor keeps the text exactly as it is; pasted as normal text, the editor turns some Markdown into its own formatting and the macro only sees the text that is left.
    • Or attach the .md file to the page and leave the macro empty. With no settings, the macro shows the attached README (README.md, readme.markdown…) or, if there is none, the first .md file.
  4. Publish the page.

To show pictures, attach the image files to the same page. The Markdown can refer to them by name or by a relative path: ![Diagram](diagram.png), ![Diagram](./images/diagram.png) and <img src="docs/diagram.png" width="400"> all show the attachment diagram.png.

Macro settings

SettingWhat it does
AttachmentOptional. The name of the .md file to show, when the page has more than one. When it is set, the text inside the macro is ignored.
Table of contentsNone (default), headings 1 and 2, headings 1 to 3, or all headings. The list appears in a box above the content.

Files ending in .md, .markdown, .mdown and .mkd are recognised.

Moving from Render Markdown

Render Markdown is built on Atlassian Connect. Atlassian ends support for Connect apps on 31 January 2027: after that date Connect apps get no fixes or updates. Render Markdown has had no new version since October 2021. Markdown Viewer is built on Forge, Atlassian's current app platform, and runs on Atlassian.

Existing Render Markdown macros are not converted automatically. Both apps can be installed at the same time, so keep Render Markdown installed until every page has been moved.

  1. Install Markdown Viewer.
  2. Find the pages that use the old macro. While signed in to Confluence, open https://<your-site>.atlassian.net/wiki/rest/api/search?cql=macro%3Dmarkdown&limit=100: it lists the pages that contain a macro named markdown, the name the old macro uses. If the list is empty, search for the pages by hand.
  3. For each page:
    • Edit the page and copy the Markdown from the old macro.
    • Type /Markdown Viewer, insert the macro, start a code block inside it (``` ` ```) and paste the Markdown. If you prefer to keep the Markdown in a file, save it as a .md file, attach it to the page and leave the macro empty.
    • If the Markdown shows images, attach the image files to the page (see Limitations).
    • Delete the old macro and publish.
  4. When no page uses the old macro, uninstall Render Markdown.

Differences to expect:

  • Code is always highlighted in Confluence's code style, using the language written after the opening ``` ` ```. The old macro's highlighting styles (themes) are not available.
  • HTML inside the Markdown is not rendered: tags are removed and their text is kept.

Limitations

  • Images: attached images and embedded images (data:image/…;base64) are shown when they are on a line of their own: alone, next to other images, or wrapped in a link or in HTML tags such as <p align="center">. Images inside a sentence show their alternative text instead. Images from other websites are not loaded, because the app does not connect to any server outside Atlassian: they are shown as a link to the image. Up to 30 attached images per macro, 3 MB each, in PNG, JPEG, GIF, SVG, WebP or BMP.
  • HTML: not rendered. Tags are removed and their text is kept; the content of <details> blocks is shown open.
  • Table of contents: entries are plain text, not links. Only headings at the top level of the document are listed (not headings inside lists or quotes).
  • Inside lists and quotes: tables are shown as lines of text, headings as bold text, and task lists with ☐ / ☑ marks instead of checkboxes. Task lists in numbered lists, or mixed with normal items, also use these marks.
  • Tables: column alignment (:---:) is ignored.
  • Not supported: math is shown as LaTeX code; Mermaid and other diagram code blocks are shown as code; emoji shortcodes such as :smile: stay as text (emoji characters work); heading IDs and [text](#heading) links to headings do not work.
  • Size: up to 1 MB of Markdown per macro. Only the first 250 attachments of a page are looked at.
  • Sources: Markdown from a URL or a Git repository is not supported: paste it or attach the file.

Permissions

ScopeWhy
read:attachment:confluenceList the attachments of the page, as the person viewing it, to find the .md file and the images the Markdown shows.
readonly:content.attachment:confluenceDownload that file or image, as the person viewing the page.

No egress: the app does not connect to any server outside Atlassian.

Data and privacy

The app stores nothing. The Markdown stays in the page, in the macro or as an attachment. Attachments and images are read with the permissions of the person viewing the page, so readers see only what they can already open, and the Markdown is converted in their browser. Nothing is logged and no data leaves Atlassian. See the privacy policy.

Troubleshooting

Some Markdown is shown as plain text, or symbols like # and * are missing

The Markdown was pasted as normal text, and the editor changed part of it. Edit the macro, put the Markdown in a code block (type ``` ` ``` and paste), and publish.

An image shows "[Image: … not attached to this page]"

Attach the image to the same page. The file name must match the last part of the path in the Markdown (./img/Logo.png looks for Logo.png); upper and lower case do not matter.

An image from a website is shown as a link

Images from other websites are not loaded, because the app does not connect to servers outside Atlassian. Download the image and attach it to the page, then refer to it by its name.

The macro shows a different .md file

With no settings, the macro shows the attached README first, or the first .md file. Name the file you want in the macro's Attachment setting.

The app says it needs an active license

The app is paid and checks the license on every request. Ask your site administrator to check the app's subscription in the administration of Confluence (Apps → Manage apps). During a free trial the app works normally.
