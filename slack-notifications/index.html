Notifications to Slack: Alerts & Reports for Jira

Send Jira issue updates and scheduled JQL reports to Slack channels.

Overview

Keep a team up to date where it already talks. Add the Slack channels you want to use through incoming webhooks and choose what reaches each one: new issues, status or assignee changes, comments or other field changes, per project and JQL. Schedule daily or weekly reports of any JQL query.

  • Rules by project, kind of change and JQL filter, each one sending to a channel.
  • Messages with the issue, what changed, who changed it and a link to Jira; comment text is optional.
  • Daily or weekly reports with the issues of a JQL query and a link to the full search.
  • Your own incoming webhooks: each URL is stored encrypted and never shown again. The app does not connect to a Slack account and reads nothing from Slack.

Getting started

  1. A Jira administrator installs the app from its Atlassian Marketplace listing.
  2. In Slack, go to api.slack.com/apps, select Create New App → From scratch, give it a name (for example "Jira alerts") and choose your workspace. The name and icon of this Slack app are the ones people see on each message.
  3. In the Slack app settings, open Incoming Webhooks, turn on Activate Incoming Webhooks and select Add New Webhook. Pick the channel and allow access. Copy the webhook URL (https://hooks.slack.com/services/…). Repeat for each channel. Your Slack workspace may require an admin to approve the Slack app.
  4. In Jira, open Settings → Apps → Notifications to Slack. In the Channels tab, type a name for the channel (for example #dev-alerts), paste the webhook URL and select Add channel. Then select Send test.
  5. In the Rules tab, select Add rule. Reports are set up in the Reports tab.

Channels

Each channel is one incoming webhook: Slack decides the channel it posts to when you create the webhook. The name you type in Jira is only a label for you.

ActionWhat it does
Add channelSaves the name and the webhook URL. The URL is checked to be a Slack incoming webhook (https://hooks.slack.com/services/…) and stored as an encrypted secret.
Send testPosts "Connected to Jira" to the channel.
EditRenames the channel or replaces its webhook URL (leave the URL empty to keep the current one). Rules and reports keep pointing to it.
RemoveDeletes the channel and its URL. A channel used by a rule or report cannot be removed.

Status: Ready, or Failing when Slack rejected the last message (hover over it to see why, for example "the channel is archived"). The next message that gets through clears it.

Rules

SettingWhat it does
ProjectsThe projects the rule applies to. Empty means all projects.
Send a message whenIssue created, status changed, assignee changed, comment added, other fields changed.
Only issues matching this JQLOptional filter, for example priority in (High, Highest). It is checked when the change happens.
ChannelWhere the message goes.
Include the comment textWhen a comment is added, the first 300 characters are included, only if the comment is visible to everyone who can see the issue (not restricted to a role or group, and not an internal Jira Service Management comment).

If several rules send the same change to the same channel, the channel gets one message.

Reports

A report sends the issues of a JQL query to a channel every day or every week at the time you choose, in the time zone of the administrator who saved it. It lists up to 50 issues and links to the full search. Send now sends it at once.

Moving from Slack Connector for Jira

Atlassian ends support for Connect, the platform used by Slack Connector for Jira, on 31 January 2027. This app is built on Forge and runs on Atlassian's cloud.

This app covers the channel notifications. It does not include a Slack bot: you cannot create, assign or search issues from Slack, issue keys are not expanded in Slack, and there is no Slack panel in the issue view.

The configuration of the other app is not copied. Set this app up in a few minutes (see Getting started):

  • Create an incoming webhook for each channel that received notifications and add it in the Channels tab.
  • Recreate the notifications of each project as rules: projects, kind of change, JQL and channel.
  • Optionally, add reports for the summaries your team reviews every day or every week.
  • When the new messages arrive, remove the other app so that each change is not posted twice.

Both apps can be installed at the same time, so you can try this one before you uninstall the other.

Limitations

  • One way only: Jira to Slack. Nothing is read from Slack and there are no actions from Slack.
  • Slack sets the name and icon of the messages (those of your Slack app) and the channel of each webhook; the app cannot change them.
  • Everyone in a channel sees its messages, including people who cannot open the project in Jira. Choose channels and JQL filters with that in mind.
  • The app reads issues as itself, so a rule can notify about issues in any project the app can see.
  • Slack accepts about one message per second per webhook. The app waits and retries once when Slack asks it to slow down; during a burst of many changes some messages may not arrive.
  • Reports run on an hourly schedule, so they may arrive a few minutes after the chosen time. Up to 50 issues per report.
  • Only standard incoming webhooks (hooks.slack.com/services/…) are supported; Workflow Builder webhooks and GovSlack are not.
  • Up to 100 channels.

Data and privacy

The app stores the webhook URLs (encrypted), the channel names you type, the last Slack error of each channel and the rules and reports (projects and JQL) in Atlassian's Forge storage. It stores no account IDs and no issue content. When a rule or report matches, it sends to Slack the issue key, summary, project, type, status, the names of the people involved and, if you choose, the text of public comments. Those messages are then kept by Slack under its own terms. Webhook URLs, issue content and names are never written to the app's logs. See the privacy policy.

Troubleshooting

Send test says the webhook was removed or disabled

The webhook was deleted, or the Slack app was uninstalled from the workspace. Create a new webhook and paste it with Edit on the channel.

The channel shows "Failing"

Hover over it to see Slack's answer. "The channel is archived": unarchive it or point the channel to a new webhook. "A Slack administrator restricted this webhook": ask your Slack admin. Then use Send test.

A rule sends nothing

Check that the rule is on, that the project and kind of change match, and that the issue matches its JQL. Only changes made after the rule was saved are sent.

The comment text is missing

The comment is restricted to a role or group, or it is an internal Jira Service Management comment. Only public comments are included.

The app says it needs an active license

Check the app subscription in Administration → Apps. Without an active license, no messages are sent.
