Overview

When two people edit the same attached document, one of them loses work. Attachment Checkout & Lock lets you check out a file before you edit it. If someone else uploads a new version while it is checked out, the app puts your version back automatically and records the attempt.

  • Check out (lock) and check in (unlock) any attachment from the page header.
  • See how many files are locked, who holds each lock and since when.
  • Automatic rollback of uploads made by other people while a file is locked.
  • A site-wide list of locks for administrators, who can release any lock.

Getting started

  1. A Confluence administrator installs the app from its Atlassian Marketplace listing.
  2. Open a page that has attachments.
  3. In the page header, under the title, select Attachment locks. When files are locked it shows the count instead, for example 🔒 2 locked.

Checking files out and in

Check out a file

The panel lists every attachment of the page with its Version and Status (Available or Locked). Select Lock next to the file. Only people who can edit the page can lock its files.

Work on the file

Download it, edit it and upload the new version as usual. Your own uploads are accepted and become the protected version.

Check it in

Select Unlock when you are done. Only the person who locked a file can unlock it from the page; administrators can release any lock from the administration page.

What happens if someone else uploads a new version

A few seconds after the upload, the app restores the locked version by uploading it again as the newest version, and records the attempt under Recent activity. The other person's upload stays in the file's version history, so nothing is lost: they can download it and talk to the lock owner.

Trash and delete

If the lock owner moves the file to the trash or deletes it, the lock is released. If someone else moves a locked file to the trash, the attempt is recorded; restore the file from the page's trash if needed.

Administration

Confluence administrators can open it from Confluence administration → Settings → Apps → Attachment locks. It shows every locked file in the site with File, Page ID, Locked by and Since, and an Unlock button to release any lock. Use Next page to see more.

Moving from Cenote Lockpoint – Attachment Checkout

Atlassian ends support for Connect, the platform used by Cenote Lockpoint – Attachment Checkout, on 31 January 2027. This app is built on Forge and runs on Atlassian's cloud.

Locks made with the other app are not copied into this one. To switch without losing protection:

  1. Install this app from its Atlassian Marketplace listing.
  2. Ask the people who hold locks in the other app to check their files in.
  3. Lock those files again with this app, from Attachment locks in the page header.
  4. Uninstall the other app.

Do not lock the same file in both apps at the same time.

Both apps can be installed at the same time, so you can try this one before you uninstall the other.

Limitations

  • Confluence cannot block an upload, so the app reverts it right after it happens. Each rollback adds a version to the file.
  • Locks protect against new versions. Renaming a file or editing its properties is not blocked.
  • Locking needs permission to edit the page.

Data and privacy

For each lock the app stores the page ID, attachment ID, file name, version number, the Atlassian account ID of the lock owner and the date, plus an activity log of the last 50 events per page (event type, account ID and date). File contents are never stored. Everything is kept in Atlassian's Forge storage; no data leaves Atlassian. Once a week the app reports the stored account IDs to Atlassian, as Atlassian requires, and when an account is closed its locks are released and it is removed from the activity log. See the privacy policy.

Troubleshooting

My new version disappeared

The file was locked by someone else, so the app restored their version. Your upload is still in the file's version history. Ask the lock owner to unlock the file, or ask an administrator.

I cannot lock a file

You need permission to edit the page, and the file must not be locked by someone else.

The app says it needs an active license

The app is paid and checks the license on every request. Ask your site administrator to check the app's subscription in the administration of Jira or Confluence (Apps → Manage apps). During a free trial the app works normally.
